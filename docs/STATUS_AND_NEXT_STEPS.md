## 2. 데이터 상태

- 위험 수준과 기본 포트폴리오는 고정 스냅샷과 모델 산출물로 재현할 수 있습니다.
- 테마 ETF 가격 데이터와 테마 정의가 준비되어 있지만, 테마 자체의 기대수익률을 독립적인 전망치처럼 제공하지는 않습니다.
- 신규 로컬 계정은 실제 NAV·보유 스냅샷이 없으므로 투자 현황이 빈 상태로 시작합니다.
- 예시 성과 데이터는 UI 확인용 결정론적 샘플이며 DB에 저장되지 않습니다.
- “최근 이슈”는 직접 선별한 정적 자료입니다. 실시간 뉴스나 자동 추천으로 표현하면 안 됩니다.

## 3. 개발팀 우선순위

### P0 — 인수 직후

1. 새 클론에서 SQLite 초기화, 로그인, 온보딩 완료, 포트폴리오 조회까지 재현합니다.
2. 운영 비밀정보와 사용자 DB가 저장소 또는 배포 로그에 없는지 확인합니다.
3. 프론트엔드·백엔드 테스트와 프로덕션 빌드를 CI에서 실행합니다.
4. 고정 스냅샷과 산출물 중 재현에 필요한 파일의 배포·재배포 권리를 확인합니다.

### P1 — 제품 일관성

1. 기존 `/performance` 화면을 새 `/dashboard` 성과 보고서 계약으로 통합합니다.
2. CORE 벤치마크와 사용자 Base 포트폴리오의 용어·비교 기준을 모든 화면에서 통일합니다.
3. 모의운용 스케줄러를 실제 운영 환경에 연결하고 NAV·보유 스냅샷을 쌓습니다.
4. 오류·빈 상태·로딩 상태를 전 화면에서 같은 문구와 컴포넌트로 정리합니다.
5. 모바일과 키보드 접근성 회귀 테스트를 CI에 고정합니다.

### P2 — 모델·데이터 확장

1. 외부 현금 유입·출금이 있는 계좌를 처리하도록 성과 계산을 확장합니다.
2. 무위험수익률 기준과 산출 주기를 정한 뒤 Sharpe Ratio를 추가합니다.
3. 테마 ETF의 기대수익률·변동성을 제공하려면 데이터 기간, 통화·환율, 배당, 상장 이력, 벤치마크와 추정 방법을 먼저 정의합니다.
4. 뉴스 기능을 실시간으로 확장할 경우 출처, 게시시각, 중복, 수정 이력과 테마 연결 근거를 저장합니다.

## 4. 알려진 한계와 주의점

- 실제 거래 계좌와 연결되지 않은 모의운용 시스템입니다.
- 성과 기여도는 현재 외부 입출금이 없는 계좌 원장을 전제로 합니다.
- 기대수익률은 장기 전략 가정이며 단기 예측이 아닙니다.
- 미국 채권 일부는 단순화한 환헤지 프록시로 환헤지 비용을 완전히 반영하지 않습니다.
- 테마는 단일 ETF 프록시이며 개별 기업 포트폴리오가 아닙니다.
- 무료 가격 데이터는 공급자 수정과 누락 가능성이 있습니다.
- 공개 배포 전 HTTPS, PostgreSQL 운영 전환, 비밀정보 관리, 백업·복구, 스케줄러, 모니터링을 완료해야 합니다.
- 로컬 테스트용 짧은 비밀번호나 생성된 세션을 운영 환경으로 옮기면 안 됩니다.

## 5. 완료 기준

개발팀 인수가 완료됐다고 볼 수 있는 기준은 다음과 같습니다.

- 새 개발자가 문서만 보고 30분 안에 실행할 수 있음
- 로컬 DB를 새로 생성해 사용자 흐름을 끝까지 완료할 수 있음
- 주요 테스트와 빌드가 CI에서 통과함
- 실제 데이터, 예시 데이터, 모델 가정이 화면과 API에서 구분됨
- 운영 전환에 필요한 P0/P1 항목의 담당자와 일정이 정해짐
