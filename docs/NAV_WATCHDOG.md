# 서버 NAV 점검·제한 재시도

## 목적과 실행 위치

개인 컴퓨터나 Codex 앱의 실행 여부와 무관하게 GitHub Actions에서 운용 NAV를
점검한다. 기존 모의운용 엔진·운영 DB·작업 레지스트리를 재사용하며 새 서버,
DB 테이블, 증권 거래 연결을 만들지 않는다.

`nav-watchdog`는 운영 기본 브랜치 `release/public-operation`에서 평일 한국 시간
18:43 / 20:43 / 22:43에 예약된다. GitHub 예약 작업은 지연될 수 있다.
기존 `daily-forward` 17:17 평가와 동일한 `forward-jobs` 동시성 그룹을 사용하며,
진행 중인 작업을 취소하지 않는다. 활성화 조건은 기존 `FORWARD_EXECUTOR=actions`,
`FORWARD_DAILY_ENABLED=true`다. 꺼져 있으면 복구를 실행하지 않고 실패 보고한다.

## 완료 판정

공동 시작 정책으로 확정된 참여자별 Personalized·CORE 계좌를 읽는다.
해당 한국 날짜에 다음 조건이 모두 충족된 계좌만 정상 저장으로 센다.

- NAV 상태 OK, stale 아님, 유한 양수, 기준 포트폴리오 버전 일치
- 평가액 = 보유자산 평가액 + 현금
- 같은 날짜의 NAV_CALCULATED 이벤트에 FORWARD_SIMULATION 출처와 일치 평가액 존재
- 합성 가격, 재현 저장소, 합성·재현 NAV 이력 없음

전체 계좌·Personalized·CORE·양쪽 완료 쌍 건수를 보고한다. 작업 success나
‘시도한 계좌 수’로 NAV 적립 완료를 추정하지 않는다. 정상 NAV가 모두 있어도
평가 작업 실패가 남아 있으면 검토 대상으로 남긴다. 첫 평가일 저장은
두 날짜 이상의 수익률 비교 완료를 뜻하지 않는다.

## 복구 경계

각 날짜의 18시·20시·22시 창마다 최대 한 번, 하루 최대 세 번만 복구한다.
같은 창의 재실행은 기존 레지스트리 잠금으로 차단한다. 중간 실패도 창을
소비한다. 프로세스가 강제 종료되어 running 기록이 남으면 자동으로 잠금을
빼앗지 않고 확인 대상으로 남긴다.

1. 정상 NAV가 모두 있으면 금융 기록·작업 기록을 쓰지 않고 종료한다.
2. 시작 정책·계좌 구성·출처가 유효하고 NAV가 누락된 경우에만 복구한다.
3. 기존 종가 수집기로 확정 가격만 추가한다. 수집 오류가 있으면 평가하지 않는다.
4. 해당 날짜의 실제 투자자산 가격이 있어야 기존 일일 엔진을 실행한다.
   환율만 최신이거나 이전 거래일 가격만 있으면 PRICE_WAIT로 남긴다.
5. 동일 `daily` 날짜·동일 DB의 원래 잠금과 성공 기록을 그대로 존중한다.
6. `--missing-nav-only`는 계좌 잠금 안에서 정상 NAV를 다시 확인하고 해당
   계좌를 건너뛴다. 나머지 계좌만 기존 확정 판단·주문·체결·평가 규칙으로 처리한다.

진행 중인 일일 작업, 성공 기록과 NAV의 불일치, 정상 NAV 이후의 미처리 주문,
검증되지 않은 기존 NAV는 자동 덮어쓰기 대상이 아니다. 강제 실행, 날짜 우회,
시작일 변경, 과거 NAV 재작성, 합성 수익률 보충은 하지 않는다.
이 기능은 현재 날짜의 누락 복구다. 휴장·가격 공급 지연과 과거 날짜의 누락은
보고되며 임의의 NAV 날짜를 만들거나 사후 실적으로 채우지 않는다.

## 운영 확인

[실행 목록](https://github.com/MinchoLover/robo/actions/workflows/nav_watchdog.yml)에서
요약과 `nav-watchdog-<run id>` 보고서를 확인한다. 보고서에는 검사 전후 건수,
상태, 재시도 여부와 가격 수집 결과가 들어간다. 미해결 누락·오류는 워크플로
실패로 표시하며 보고서 업로드는 항상 시도한다. 알림 수신은 사용자의 GitHub
알림 설정을 따른다. 자동 코드 수정이나 AI 장애 분석을 클라우드에 배치한 것은 아니다.

수동 실행은 기본적으로 읽기 전용 검사다. `repair=true`로 실행해도 동일한
시간 창·시작 정책·출처·잠금 검사가 적용된다. 운영 DB에 결함을 주입해 시험하지 않는다.

## 검증

새 watchdog과 기존 일일 운용·잠금 테스트를 격리 SQLite/PostgreSQL에서 실행한다.
30계좌 정상 적립, 가격 지연 후 복구, 부분 실패 계좌만 복구, 정상 계좌 원장 보존,
동시 호출·창별 중복 차단, 출처 차단, 기존 NAV 이상 시 중단을 검증한다.
기존 금융 엔진 계산은 재사용했다. 코드 작성·테스트·배포 검증에 AI를 사용했으며
테스트 자료는 운영 실적으로 사용하지 않았다.

로컬 검증 결과: 전체 백엔드 853개 통과(격리 SQLite/PostgreSQL), 이후 잠금
중단 판정 보완을 포함한 최종 감시 테스트 50개 통과. 집합이 중복되므로 합산하지 않는다.
PostgreSQL에서 작업 ID 길이 제한과 문자열 매개변수 처리를 확인·보완했다.
정상 계좌 기록 보존 검사에서는 전역 재시도 감사 이벤트와 계좌별 금융 기록을
구분했다. 검사 명령은 `python -m pytest tests --ignore=tests/backup -q` 및
`python -m pytest tests/forward/test_nav_watchdog.py -q`이며, PostgreSQL 대상은
로컬의 TEST_* 환경변수로 지정한 임시 테스트 DB뿐이다.
