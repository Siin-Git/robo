# 주요 페이지 문구·화면 정리

## 범위와 판단 기준

대시보드, 내 포트폴리오, 주간 투자 의견, 포트폴리오 성과, 판단 기록,
투자 전략 자료실, 참여자 비교, 계정 관리의 8개 페이지를 점검했다.
기존 다크 색상·카드·버튼을 사용하고, 정보의 중복과 서로 다른 명칭을 줄인다.
새 기능이나 금융 계산 변경은 포함하지 않는다.

- 대시보드: 두 영문 표제와 반복 소개를 없애고, 투자 현황과 상세 이동을 먼저 표시.
  모바일에서도 포트폴리오 이동 버튼을 유지한다.
- 포트폴리오·성과: 장식용 영문 표제를 제거. 구성 비중은 ‘목표 자산 구성’으로
  명시하고 마우스 조작만 설명하는 문구를 제거.
- 주간 의견: 독립된 규칙 사이드 카드를 선택 영역 위의 펼침 설명으로 통합.
  최대 2개 선택과 15%/10% 한도는 접힌 상태에서도 표시한다.
  내부 테마 ID·상태 문자열 대신 테마명·의견 상태·적용 기준일·체결 상태를 표시.
  EXECUTED는 ‘체결 기록 있음’이며 의견 전체의 완전한 집행을 보증하지 않는다.
  조회 실패를 저장 기록 없음으로 오인하지 않도록 별도 오류와 재시도를 표시.
- 판단 기록·전략 자료: 메뉴와 제목을 맞추고 복귀 링크를 기존 보조 버튼으로 통일.
  전략 카드의 장식 번호와 반복 설명을 제거.
- 참여자 비교·계정 관리: 반복 소개를 줄이고 로그인 내역·권한 명칭을 읽기 쉽게 정리.

최초 판단, 과거 재현/실제 관측 구분, 가격/기간/비교 조건, 자료 부족 안내,
유지·조정 동작, 제출 및 모의운용 정책은 그대로 유지한다.

## 재현

```sh
cd web
npm test
npx tsc --noEmit
NEXT_PUBLIC_CAPSTONE_DEMO=1 NEXT_PUBLIC_LAB_MEETING=1 npm run build
cd ..
.venv/bin/python web/e2e/run_rehearsal.py
```

`page-consistency.spec.ts`는 격리된 실제 API와 새 SQLite 데이터베이스에서
8개 페이지를 1440px/390px로 방문하고 가로 넘침, 브라우저 오류,
규칙 설명의 키보드 펼침, 조회 전후 투자 기록 불변성을 확인한다.
기존 확정 전 비교·구성 선택·검토 저장 흐름도 함께 검사한다.
화면 증거는 `docs/evidence/page-consistency/`에 있다. **격리 테스트 계정이며
운영 성과의 증거가 아니다.** 자동 테스트는 화면 품질의 모든 측면을 보증하지 않으므로
주요 화면의 시각 점검도 수행했다.

AI 사용: 기존 코드·API 계약과 배포 화면을 검토한 뒤 문구·CSS 변경 및 회귀 검사를
작성했다. 예상 수익률·관측 기록·거래를 생성하지 않았다.

검증 결과: 프런트 146개, 실제 API 브라우저 6개, 타입 검사·production 빌드 통과.
페이지 순회 전후 판단·선택·주문·체결·NAV 등 투자 기록 수가 동일했다.
