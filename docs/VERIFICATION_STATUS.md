# 검증 현황 페이지

## 구현 범위

교수·참여자가 자신의 최신 판단에 대해 확인된 근거와 미확인 항목을 한 화면에서
읽는다. 성과 분석 메뉴 → 검증 현황 → 세 카드의 근거 펼침 → 판단/성과 상세 흐름이다.
완료 기준은 기존 스타일의 반응형 화면, 실제 소유자 API 연결, 출처/기준일 표시,
미확인·실패·갱신 실패 구분, 읽기 전용 동작 검증 및 운영 배포다.

P0: 판단 기록 / 동일 기간 성과 / 전체 계좌 작업의 분리, 근거 펼침,
3·6개월 검토 상태와 미입증 항목, 버전이 고정된 기능 검사 기록.
새 금융 계산, 운용 실행, 관리자 전용 자료 공개, 성과 우위 판정, 검증 점수는 제외한다.

## 설계 결정

- 새 집계 API나 DB 대신 기존 `/api/v1/me/decisions`와 최신 판단의
  `/verification`을 재사용한다. 기존 서버 소유권 검사와 재생/합성 자료 제외 조건을
  유지한다. 판단이 없으면 해당 계정 근거는 미확보로 표시한다.
- 판단을 읽었다는 사실과 불변성 검사를 통과했다는 사실은 별개다.
  실시간 카드에는 ‘저장 기록 확인’만 표시하고, 불변성 회귀 검사는 버전 고정된
  검사 기록에 연결한다. 누락된 예상이나 비중은 다른 자료로 채우지 않는다.
- 성과는 서버 AVAILABLE뿐 아니라 날짜, 공통 관측 수, 양쪽 NAV·수익률 필드가
  있어야 표시한다. 0은 유효한 수익률이며 결측은 ‘—’다. Base와 CORE를 구분한다.
- 평가 작업은 전체 계좌 범위다. 작업 성공만으로 NAV 완료를 표시하지 않는다.
  NAV_COMPLETE와 valuation_completed=true를 함께 요구한다. 최근 작업 기준일과
  완료 시각을 별도로 표시하며 현재 계정의 성과 확보를 보증하지 않는다.
- 기능 검사 결과는 검증된 커밋·실행 URL·완료 시각을 명시한 고정 기록이다.
  GitHub에서 런타임 조회하지 않으므로 최신 CI처럼 표시하지 않는다. 갱신 시 실제
  로그 확인 후 기록 파일을 수정한다. API 조회 시각과 검사 완료 시각을 섞지 않는다.
- 3·6개월 상태는 서버 값을 그대로 읽는다. 검토 기록 존재가 예측 적중을 뜻하지
  않는다. 지속적 초과성과·사용자 효용은 등록된 근거의 한계를 명시한다.
- 최초 조회 실패는 미확보와 구분한다. 재조회 실패 시 이전 근거를 남기되 카드의
  성공 표시를 ‘갱신 실패’로 바꾸며, 마지막 성공 조회 시각을 유지한다.

## 검증 계획

프런트: 기록 누락, 0 수익률, 비교 필드 누락/미확보, 작업 성공과 NAV 완료 구분,
과거 캐시 갱신 실패, 판단 없음, 3·6개월 기록과 성과 판정 분리를 확인한다.
격리 실제 API 브라우저: 새 메뉴, 소유자 근거, 접기/키보드, 새로고침,
실패→재시도, 390/320px, 읽기 전후 원장 불변성, 합성 NAV 차단을 확인한다.
실행 결과: 프런트 167개, 검증 API 28개, 격리 실제 API 브라우저 7개,
production 빌드(타입 검사 포함) 통과. 기존 의존성을 재사용했고 변경/설치는 없다.
브라우저 검사에서 로그인 완료를 기다리도록 이동 순서를 보완하고, Next 라우트
알림과 페이지 오류 알림을 구분하도록 검사 선택자를 수정했다. 최종 검사 7개 모두 통과했다.
조회·새로고침은 투자 기록을 변경하지 않았으며 합성 NAV는 성과 비교에서 제외됐다.
