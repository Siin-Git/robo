# 자산 한 건의 내부 검토 사례

`/verification`의 02 섹션에서 로그인한 계정의 최신 확정 판단에 속한 자산 한 건을 조회한다.

## 교수님께 보여줄 순서

1. **최초 예상**: 확정 당시 저장된 자산별 연수익률·연변동성·비중을 읽는다. 미저장 값은 미확보다.
2. **이후 관측**: 같은 판단 효력일 이후 저장 가격의 시작·끝과 변화율을 읽는다. 두 날짜가 없으면 계산 대기다.
3. **자료 기준 검토 결과**: 지금 유지·수정을 판정할 근거가 충분한지 설명한다. 현재는 비교 정의가 미합의이므로 Revision 판단은 보류다. 담당자의 실제 검토가 저장됐다고 표현하지 않는다.
4. **선정 이유와 원본 관측값**을 펼쳐 날짜·가격·출처와 3/6개월 시점을 확인한다.

발표 문안: “처음 예상과 이후 기록을 자산 하나로 연결해 봤습니다. 여기서 원래 예상은 그대로 보존하고, 실제 저장된 가격만 가져왔습니다. 지금은 화면에 나온 자료 제약 때문에 유지나 수정으로 결론 내리지 않고 보류했습니다. 어떤 기준과 기간을 확보한 뒤 다시 검토할지도 함께 적었습니다.”

## 검증 근거

| 확인 대상 | 재현 경로 | 확인 내용 |
|---|---|---|
| 원본 보존·기간·가격 검산 | `tests/api/test_asset_review_case.py` | 모형을 바꿔도 원본 불변, 100→110=10%, 미래·이전 판단 구간 제외, 조회 전후 원장 불변 |
| 권한 | 같은 파일 | 미로그인 401, 다른 사용자 404, 관리자 원본 접근 403 |
| 자료 부족·출처 | 같은 파일 | 원본 미저장 소급 생성 금지, 한 날짜 수익률 null, 시험·재생·미확인 출처 제외 |
| 기존 내부 추적·검증 | `tests/api/test_internal_tracking.py`, `tests/api/test_decision_verification.py` | 기존 보존·추적·비교 규칙 회귀 검사 |
| 화면·오류 | `web/components/__tests__/AssetReviewCase.test.tsx` | 연간 예상과 기간 결과 분리, 다른 판단 값 잔류 방지, 최초/갱신 실패, 출처 제외 |

API의 `assessment.kind=DATA_SUFFICIENCY_CHECK`, `recorded_human_review=false`, `changes_model_or_orders=false`를 유지한다. 이 기능의 검사 통과는 미래 성과나 예측 정확도를 입증하지 않는다.
