# 선택 위험과 재검토 시점

## 구현 범위

- 대상: 확정한 포트폴리오를 보는 사용자. `/portfolio`의 저장된 Frontier 점을 선택한다.
- 핵심 문제: 현재 모형의 변화량만으로는 확정 당시 선택이 기본 구성의 위험을 얼마나 바꿨는지 확인할 수 없고, 재검토 날짜도 알기 어렵다.
- 완료 기준: 본인 판단의 확정 당시 동등한 위험 계산값이 있으면 Base와 Personalized 연율 변동성 및 변화량(%p)을 표시한다. 자료가 없으면 미확보를 표시한다. 공동 운용 시작일을 고려한 3개월·6개월 달력 점검일과 기록 상태를 보여준다.
- 비대상: 실현 변동성으로 예상 위험을 대체하거나, 수익률로 판단의 적중을 자동 판정하거나, 위험 임계값과 자동 매매 규칙을 새로 정하는 일.

## 결정

1. **위험 변화의 출처.** 현재 summary API의 재계산값 대신 최초 확정 시 `portfolio_decisions.provenance_json.risk_comparison`에 저장된 동일 모형·자료일의 Base/Personalized 두 값을 사용한다. 다른 출처의 두 변동성을 혼합하지 않는다. 누락·비정상·방법/날짜 미기록은 미확보로 표시한다. 새 저장소는 필요 없다. 이미 확정된 판단을 다시 계산하거나 덮어쓰지 않는다.
2. **점검일의 의미.** 판단 효력일과 저장된 forward 시작일 중 늦은 날짜를 달력상 기준일로 삼아 3개월·6개월 날짜를 만든다. 날짜는 사용자의 점검 안내이며 예측 유효기간·자동 주문 신호가 아니다. 정상 Personalized/CORE NAV가 해당 점검일 이후까지 확보되지 않으면 자료 대기로 표시한다. 이후 정상 공통 기록이 있으면 재검토 안내를 표시한다. 해당 기간에 저장된 KEEP/ADJUST 이유는 검토 기록으로 표시한다. 후속 판단이 먼저 효력을 얻으면 구 판단의 이후 점검은 종료한다.
3. **화면.** 기존 3개 섹션과 다크 레이아웃을 유지하고 당시 판단에는 위험 변화, 가정 재검토에는 두 점검일을 추가한다. 사용자의 투자 이유나 감내 가능한 위험이 변했는지는 자동 감지하지 못한다고 설명하고 기존 판단 검토 화면으로 연결한다.

## 확인 경로

1. 운영 계정으로 `/portfolio` 접속 후 Personalized 점을 클릭한다.
2. 당시 Base·Personalized 변동성, 변화량과 자료 기준일을 확인한다.
3. 3개월·6개월 점검일, 자료 대기/재검토/기록 상태를 확인한다.
4. 원본 판단과 NAV, 기존 검토 기록이 바뀌지 않는지 테스트로 확인한다.

## 자료 한계

과거 재현 가격은 판단 이후 정상 운용 NAV를 대신하지 않는다. 달력상 점검일이 지나도 충분한 가격과 양쪽 계좌 NAV가 없으면 금융적 판단을 단정하지 않는다. 시장 전망의 변화나 투자자 위험 선호의 변화는 사용자가 근거를 검토해야 한다.

## 검증 기록

- 격리된 SQLite API 판단 검증 테스트: 28개 통과. 저장된 동일 모형의 위험 쌍만 표시하며 누락·비정상 값을 보충하지 않는다. 3·6개월 말일, 자료 대기, 후속 판단, 두 시점의 검토 이력을 검증했다.
- API·운용 관련 백엔드 전체 검사: 642개 통과, 54개 건너뜀. 로컬에서 PostgreSQL 등 별도 환경이 필요한 검사는 CI 결과로 추가 확인한다.
- 프런트 단위 테스트: 127개 통과. 프로덕션 빌드와 타입 검사는 통과했다.
- 격리 계정과 실제 API를 사용하는 브라우저 테스트: 2개 통과. 키보드, 저장 후 재조회, 390px 모바일, 합성 NAV 제외를 검증했다. 계정·비밀번호와 DB는 `/private/tmp`에만 보관했다.
- 화면 증거: [당시 위험 변화](evidence/decision-risk-review-ui/risk-change-desktop.png), [3·6개월 점검일](evidence/decision-risk-review-ui/review-checkpoints-desktop.png), [모바일](evidence/decision-risk-review-ui/mobile.png). 이 캡처는 격리 테스트 계정이며 운영 성과가 아니다.

Codex가 기존 API와 화면을 연결하고 회귀 테스트를 작성했다. 숫자의 출처, 원본 판단 보존, 자료 부족 처리 및 기간별 검토 기록은 위 테스트와 브라우저 실행으로 확인했다. 추정 위험이 투자자의 실제 손실 위험을 얼마나 설명하는지에 대한 독립적인 금융 검증은 별도 과제다.
