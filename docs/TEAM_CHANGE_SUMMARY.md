# 팀 공유: 가입부터 성과 비교까지 한 앱으로 연결

## 이번에 변경한 부분

- 실제 회원가입과 기존 세션을 이용하는 첫 설정을 추가했습니다. 공통 CORE 확인 → Theme 최대 2개·이유 → 기존 디자인의 최종 비중 확인 → 생성 → 비교로 이어집니다.
- 초대 이메일에 묶인 12+1 또는 11+2 비교군을 명시적 명령으로 준비합니다. 전체 계정 수를 13명으로 제한하거나 기존 사용자를 삭제하지 않습니다.
- 자유 설계의 예상 위험 지표가 비어 있던 원인은 분리 DB의 가격 누락이었습니다. 기존 v1 가격 이력만 연결해 같은 Backend 계산을 복구했습니다.
- 확정 실험 구성은 자유 설계와 별도로 저장합니다. 동일 Theme·비중의 공개 시나리오만 가상 결과에 연결하며, 없는 조합은 성과 집계 대기입니다.
- Race, Risk–Return, 지표별 랭킹·내 행 강조, 상대 순위, TE/IR, 데이터 기준 주간, Theme 선택자 평균을 기존 Backend 결과로 연결했습니다.

## 교수님께 바로 보여드릴 수 있는 부분

로컬 및 배포 앱에서 예약된 이메일로 가입해 CORE·Theme를 직접 선택하고 다른 참가자와 비교할 수 있습니다. 기존 Theme 카드와 미리보기 디자인을 유지합니다. 지원 조합 목록과 가상 NAV 안내를 화면에서 확인할 수 있습니다. 반복 방법은 [시연 운영 안내](UNIFIED_DEMO.md)를 따릅니다.

## 다음 회의 전에 개선할 부분

- 배포 환경의 가입 데이터 영속 저장을 먼저 결정해야 합니다. 현재 Render 임시 SQLite는 재배포 시 신규 가입 데이터를 잃을 수 있습니다.
- 실제 Forward Test 시작·위험 검증·정기 평가 작업을 확정 구성과 연결해야 합니다.
- 현재 제공되는 기준 주간은 2026-09-07~09-11의 가상 시연 데이터입니다. 최신 주간 브리핑에는 최신 결과와 공통 기간이 필요합니다.

## 다른 팀에서 제공해야 할 데이터/API

Sortino 정의·결측 정책, 동일 구성/기간의 실제 holdings·trades·prices, 실제 적용 비중, 자산·Base·Theme별 누적/주간 Contribution 및 비용·잔차, 실제 Forward 시작일과 주간 마감 정의가 필요합니다. Theme 총수익 기여도와 CORE 초과성과 기여도를 다른 필드로 제공해야 합니다.

## 알려진 제한

- 과거 NAV는 가상 시연 결과이며 신규 사용자의 실제 운용 이력이 아닙니다. Theme 선택마다 수익률을 새로 생성하지 않습니다.
- 임의 조합의 실적과 Contribution을 만들지 않습니다. 성과 없는 참가자는 등록 인원에는 포함되지만 순위에서는 제외됩니다.
- 공통 CORE의 현재 목표 위험 기준은 약 8.92%입니다. 통화의 5%는 현재 설정과 일치하지 않아 금융팀 확인이 필요합니다.
- Vercel + 무료 Render의 단기 시연 배포를 진행했습니다. 별도 PostgreSQL migration·유료 저장소 설정은 하지 않았습니다. 원격에는 v1 가격 이력이 없어 일부 예상 위험값은 미지원이며 로컬 검증과 구분합니다. 상세 배포 결과는 통합 기록을 참고하세요.

## main 통합 추가 확인

원본 main이 캡스톤 브랜치의 조상인 것을 확인하고 별도 `integration/v1-capstone`에서 통합했습니다. 기존 금융 서비스는 main과 동일하게 유지했습니다. 자유 설계에서 기존 운용 대시보드로 가는 경로를 연결하고, 서버 전용 초대 해시 설정과 재실행 보호를 추가했습니다. 기존 v1·캡스톤 브라우저 회귀 4개, Backend 144개, Frontend 45개가 통과했습니다. 배포와 영속 저장소 제한은 [통합 기록](V1_CAPSTONE_INTEGRATION.md)에 정리했습니다.

최종 앱 주소: https://robo-q3o3.vercel.app . 신규 가입 브라우저 2건(데스크톱/모바일)은 실제 배포에서 생성·비교·상세까지 통과했습니다. 발표자 이메일은 `demo@example.com`이며 초대 코드 원문과 새 비밀번호는 Git에 저장하지 않습니다.
