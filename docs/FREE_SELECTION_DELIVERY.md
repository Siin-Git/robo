# 자유 선택과 재구성 연결

사용자가 최대 두 Theme와 선택 이유를 저장하면 현재 구성의 가격 기반 과거 비교를 대시보드, 순위, 상세에서 함께 보여준다. 재구성은 본인만 수행하고 다른 참가자의 계정 및 과거 장부를 변경하지 않는다.

## 결정

- 기존 가상 NAV는 삭제하거나 실제 운용 이력으로 바꾸지 않는다. 비교 화면은 모든 참가자를 동일한 시장 가격·기간·계산법으로 다시 평가한다. 신규 사용자만 실제 가격 결과를 기존 가상 순위에 섞지 않는다.
- 기존 가격 저장소의 시장 데이터만 배포 가능한 압축 CSV로 추출한다. 계정, 비밀번호, 세션 및 개인 포트폴리오는 포함하지 않는다. 출처·기간·해시를 manifest에 기록한다.
- 현재 목표 비중을 공통 시작일에 투자한 매수 후 보유 평가를 사용한다. 실제 운용 및 투자 시점에 알려진 전략의 검증 결과가 아니라는 점, 비용·세금 미포함을 화면에 표시한다.
- 재구성의 최신 확정 비중은 기존 설계 DB에서 조회한다. 초안은 순위에 반영하지 않는다. 최초 실험 구성과 기존 NAV는 보존한다.
- 시연 프로필의 `CAPSTONE_MARKET_COMPARISON=1`로 전환한다. 일반 운영 프로필의 계산·DB는 유지한다.
- 무료 Render의 임시 SQLite가 재배포 때 사라질 수 있음을 설명했고, 사용자가 2026-09-20 재가입을 허용하고 배포를 승인했다. 별도의 수동 DB 삭제·초기화는 실행하지 않았다.

## 배포 설정과 데이터 보존

Backend에 `CAPSTONE_MARKET_COMPARISON=1`을 설정하고 `data/market/`를 포함한다. Frontend는 API의 `market_comparison`과 `data_source`에 따라 표시하며 새로운 공개 환경변수는 필요 없다.

2026-09-20 현재 무료 Render는 Shell/SSH 접근이 없어 실행 중인 SQLite의 비밀번호 해시를 백업할 수 없다. 사용자의 재가입 허용 후 기존 시작 명령을 유지해 배포했다. 시작 명령은 임시 DB에 시연 계정과 서버 초대 cohort를 준비하므로 신규 가입·재구성 데이터의 영속성 제한은 남아 있다.

## 본인 포트폴리오 초기화 — 2026-09-20

- 목적: 초대 가입자가 같은 계정으로 첫 설정 시연을 반복한다. 내 포트폴리오/대시보드에서 초기화 확인 → 빈 첫 설정 → 재확정 → 순위 복귀.
- `POST /me/experiment/reset`은 현재 로그인한 예약 참가자만 허용하고 CSRF 및 명시적 확인을 요구한다. 기존 준비 계정 12명이나 다른 participant를 지정할 수 없고, 실제 운용 시작 이후에는 거절한다.
- 계정·비밀번호·participant·초대 슬롯 소유권·기존 목표 비중과 NAV를 유지한다. 초기화 전 구성은 감사 기록에 남기고 현재 구성만 해제한다. 슬롯은 재가입용으로 반환되지 않는다.
- 별도 설계 저장소에는 초기화 이벤트를 한 번 적용해 기존 선택을 비활성화하고 View를 종료한다. 기록은 삭제하지 않는다. 가격 비교는 초기화 전 설계를 제외하며, 다시 확정한 구성을 사용한다.
- 초기화는 초대 가입자에게 제공한다. 기존 준비 계정의 일괄 초기화, 계정 삭제, 운용 기록 삭제는 제공하지 않는다.

- 최초 가입·초기화 후에도 재구성과 같은 변동성 선택 → Theme 선택 → 비교·확정 화면을 사용한다. 예약 참가자의 첫 저장은 기존 슬롯에 연결하며 참가자/계정을 새로 만들지 않는다.
- 개인 포트폴리오의 기본 비중은 선택한 Frontier를 반영한다. 공통 CORE는 모두에게 동일한 비교 벤치마크로 유지한다.
- 시장 가격 비교 모드에서는 선택 이유를 요구하지 않는다. 입력란과 현재 구성의 이유 안내를 제거하고, 기존 API 필드는 하위 호환을 위해 선택적으로 유지한다.
- 내 포트폴리오·참가자 상세 구성은 자산 비중 도넛 차트와 색상 범례 목록으로 표시한다.
- Portfolio Race에 내 포트폴리오/CORE/다른 참가자 색상 범례를 추가하고 CORE 초과 인원 KPI를 제거한다.
