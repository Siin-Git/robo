# 구현 범위와 검증 기록

## 브리프

교수님에게 “13명 동일 CORE + 최대 2개 View” 비교 실험을 안정적으로 클릭 시연한다.
핵심 흐름은 Login → Personal Dashboard → Ranking → Participant Detail → 계정 전환이다.
완료 기준: 13개 계정, 공통 데이터 기간·CORE, 7개 KPI, 5개 정렬 기준, 상세 구성 조회,
기존 권한 유지, 새로고침/계정 전환 시 지표 일관성.

## 결정과 대안

1. 기존 인증·DB 모델을 유지하고 별도 SQLite 파일로 seed한다. 기존 DB에 합치는 대안보다
   기존 로컬 데이터 보존과 13명 제한이 명확하다. 공개 운영 전환 때 재검토한다.
2. 실제 운용 엔진 재생 대신 결정론적 NAV fixture를 사용한다. 금융 로직 변경 없이 시연에 집중한다.
   화면에 가상 데이터를 표시한다. 실운용 연결 시 데이터 공급 경로를 교체한다.
3. 기존 비교 화면을 모두 대체하는 대신 데모 모드에서만 공통 성과 컴포넌트를 사용한다.
   일반 프로토타입의 설계·기여도 화면을 유지하는 대신 모드별 진입점을 관리해야 한다.
4. 하나의 Python 서비스에서 지표를 계산한다. 각 화면에서 별도 산출하는 대안을 배제해
   Return/Excess/MDD/Volatility/Sharpe의 불일치를 방지한다.

## AI 사용 및 확인

Codex가 저장소 분석, seed/API/UI 작성, 테스트와 문서를 수행했다.
금융 계산은 기존 `forward.metrics.perf_metrics`, 테마 비중 조달은 기존 함수를 재사용했다.
실제 브라우저 자동화는 Playwright + 설치된 Chrome으로 수행했다.
기존 계정 로그인·대시보드·랭킹·API는 구현 전에 HTTP 200으로 확인했다.

기존 전체 테스트 실행 중 개발자 `.env.local` 영향, 인증 쿠키 잔존, Windows 절대 경로,
저장소에 없는 private live DB 의존이 발견되었다. 제품 인증을 변경하지 않고 테스트의
환경을 격리하고, 익명 요청의 쿠키를 명시적으로 비우고, 경로와 migration fixture를 이식 가능하게 보정했다.

Git 저장소는 작업 시작 시 커밋이 없는 상태이며 `robo/`가 전체 미추적 상태였다.
원격 push/배포는 요청되지 않아 실행하지 않았다. 기존 파일·로컬 DB를 삭제하거나 초기화하지 않았다.
