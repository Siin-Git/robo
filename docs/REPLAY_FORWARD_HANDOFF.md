# 과거 재현에서 자동 모의운용으로 승계

## 목적과 완료 조건

2026-10-01~2026-10-24의 저장된 시장 가격으로 현재 확정 구성을 재현하고, 마지막 보유 수량·현금을 2026-10-26 자동 모의운용에 인계한다. 원래 투자 판단의 날짜와 예상치는 보존한다. 당시 확정되지 않은 구성의 사후 재현을 실제 과거 운용이나 판단 적중으로 표시하지 않는다.

- 기존 15명/30계좌가 모두 준비되어 있고 운영 NAV·체결·보유가 없어야 한다.
- 실제 관측 가격만 사용한다. 첫 공통 가격일, 마지막 관측일, 자산별 적용 가격 날짜를 기록한다. 요청한 달력 기간과 실제 평가 기간이 다를 수 있다. 휴장일의 가짜 평가를 만들지 않는다.
- 기존 체결·비용·평가 엔진을 별도 임시 SQLite에서 실행한다. 최초 매수 후 보유하는 재현이며, 과거 리밸런싱이나 당시 판단을 만들어내지 않는다.
- 재현 종료 NAV = 보유 수량 × 마지막 평가 가격 + 현금. 이후 평가·매수·매도는 승계 수량·현금에 이후 체결을 더한다.
- 실패 시 전부 롤백, 동일 계획 재실행은 무변경, 입력 변경은 새 검토가 필요하다.

## 저장과 원본 보존

새 테이블이나 서비스는 추가하지 않는다. 기존 이벤트 저장소에 계좌별 `REPLAY_FORWARD_OPENING`, 개인별 `HISTORICAL_REPLAY_ARCHIVED`, 전체 `REPLAY_HANDOFF_APPLIED`를 추가한다. 운영 체결과 NAV에 과거 재현 행을 복사하지 않는다. 기존 계좌 초기자본과 판단은 변경하지 않는다.

계획에는 원본 판단, 계좌, 준비 명단, 기존 대기 주문, 사용 가격, 비용 설정의 해시를 포함한다. 적용 시 관련 운영 테이블을 잠그고 다시 대조한다. 승계로 대체되는 기존 초기 대기 주문은 삭제하지 않고 `cancelled` 및 사유 이벤트로 남긴다. 공유 시작일 등록, 주문 취소, 재현 보관, 승계 잔액은 단일 트랜잭션이다.

향후 판단 변경은 기존 주문 정책을 따른다. 최초 판단의 이미 적용된 주문 표식을 승계와 함께 기록하여 첫 자동운용에서 다시 초기 매수하지 않게 한다. 순수 자동운용 성과와 판단 검증 API의 기존 출처 검사는 유지한다.

## 읽기 계약과 화면

`GET /api/v1/me/performance/continuity`는 로그인 사용자의 승계 판단 소유권을 확인한다. 같은 재현 실행의 개인·CORE만 결합한다. 각 점에 `HISTORICAL_REPLAY` 또는 `FORWARD_SIMULATION`을 표시한다. 자동운용 점은 정상 공동 NAV와 해당 승계 실행의 평가 이벤트가 모두 있어야 유효하다. 누락·불완전 평가는 공백이다.

대시보드의 연속 모의운용 구역은 전체 기간을 첫 재현 평가액=100으로 표시한다. 기존 자동운용·과거 재현의 별도 화면과 순위 계산은 유지한다. 승계 전후의 서로 다른 출발 평가액을 자본 금액 순위로 해석하지 않는다. 연간 기대수익률을 단기 성과와 비교하여 적중 여부를 단정하지 않는다.

## 운영 순서

1. 격리 SQLite/PostgreSQL 테스트 및 프런트 빌드, 코드 검토.
2. 백엔드를 해당 커밋으로 배포하고 상태 확인. 브랜치를 병합하여 프런트와 Actions 코드를 일치시킨다.
3. `replay-forward-handoff`를 `apply_hash` 없이 실행한다. 운영 원본은 DB가 강제하는 읽기 전용으로 읽고, 재현은 운영 연결 정보가 제거된 자식 프로세스의 임시 DB에서 수행한다. 원본 자료/개인별 잔액은 공개 로그·아티팩트에 올리지 않는다.
4. 인원·기간·취소 대기 건수·관측 수·SHA256을 검토한다. 같은 워크플로의 `apply_hash`에 그 값을 전달한다. 재실행해 새로 얻은 계획이 같을 때만 적용한다.
5. 적용 영수증과 로그인 화면을 확인한다. 26일 전에는 `AWAITING_T0`, 운영 NAV 0건이 정상이다. 26일 이후 실제 수집 가격으로 정상 평가가 이루어져야 자동운용 관측 수가 증가한다.

기존 `daily-forward`의 가격 수집/평가와 `forward-jobs` 동시 실행 잠금을 재사용한다. 로컬 컴퓨터가 켜져 있을 필요가 없다. 운영에서 테스트 날짜로 시간을 바꾸거나 미래 NAV를 생성하지 않는다. 실증권 계좌 주문은 이 경로에 없다.
