# 13명 랩미팅

## 목적과 완료 기준

참가자 13명이 각자 로그인 → 기본 위험 수준·섹터/Theme 최대 2개 선택 → 저장 → 같은 과거 가격 기간의 수익률·위험·순위 비교를 진행한다. 미완성 참가자는 순위에서 제외하고, 저장·재구성한 결과가 다른 참가자의 비교 화면에 10초 주기로 반영된다. 같은 선택은 같은 계산과 동률 규칙을 사용한다.

## 실행

`robo` 디렉터리에서:

```bash
.venv/bin/python scripts/start_lab.py --lan
```

첫 실행은 필요한 앱 빌드를 만든다. 코드 변경 후에는 `--rebuild`를 추가한다. 개발할 때는 `--dev`를 사용한다. 프론트엔드 3002, 백엔드 8002이며 각각 `--port`, `--api-port`로 바꿀 수 있다. 백엔드는 이 컴퓨터에서만 접속하며 다른 기기는 웹의 같은 출처 프록시를 사용한다.

- 진행자: `http://127.0.0.1:3002/login`
- 같은 네트워크 참가자: `http://진행자컴퓨터의LAN주소:3002/login`
- 참가자 아이디: `capstone01@example.com` ~ `capstone13@example.com`
- 개인별 초기 비밀번호: `.work/lab-meeting/accounts.md` (파일 권한 0600). 각 사람에게 본인의 행만 전달한다. 기존 데모의 공통 비밀번호와 다르다.

모두 가입이 완료된 상태다. 회원가입·초대 코드를 입력할 필요가 없다. 첫 로그인은 빈 포트폴리오 설계로 이동한다. 진행자는 `/ranking`을 열어 선택 완료 인원과 순위를 볼 수 있고, 아직 선택하지 않은 계정도 이 화면은 열 수 있다. 이름은 참여자 01~13이다.

다른 네트워크에서의 접속은 별도 외부 주소가 필요하다. LAN 주소는 인터넷 공개 주소가 아니다. 랩미팅 동안 진행자의 컴퓨터와 서버를 켜둔다. 와이파이의 기기 간 통신 차단 여부는 참가자 기기에서 확인한다.

## 비교 기준과 보존

기존 `market_comparison` 엔진 및 저장소의 가격 파일을 재사용한다. 2026-04-01~2026-09-11의 같은 기간에 현재 저장한 비중으로 최초 매수 후 보유한 결과를 비교한다. 비용·세금은 제외하며 실제 계좌 운용 기록이나 앞으로 발생할 실시간 수익이 아니다. 기본 배분은 선택한 위험 수준을 반영하고 모든 참가자의 비교 벤치마크 CORE는 동일하다. 금융 계산식·가격 파일·실거래 엔진을 변경하지 않는다.

랩미팅 데이터는 `.work/lab-meeting/capstone_demo.db`, 자유 재구성은 같은 디렉터리의 `portfolio_design.db`에 저장한다. 재실행은 기존 비밀번호·선택·초안을 유지한다. 기존 `data/`의 시연 계정·기록은 변경하지 않는다. 과거 NAV·사전 배정된 섹터를 새 계정에 넣지 않는다. 새로운 랩미팅을 빈 상태로 만들려면 별도의 `--data-dir .work/lab-meeting-다른이름`을 사용한다. 계정 파일과 두 DB를 함께 보관한다.

## 설계 결정과 범위

기존 12+1 시연 비교군을 덮어쓰는 대신 별도 DB에 0+13 비교군을 만든다. 13명 모두 기존 예약 슬롯·첫 설정·재구성·인증·CSRF 경로를 재사용하며 선택하지 않은 참가자가 사전 구성으로 순위에 들어가는 것을 막는다. 계정별 비밀번호로 다른 사람의 계정을 우연히 사용하는 것을 줄인다. 별도 계정 관리 UI, 이름 편집, 장기 실운용, 인터넷 배포·새 유료 서비스·Git push는 이번 작업 범위에 포함하지 않는다.

## 요청된 인터넷 배포 준비

2026-09-22 사용자가 인터넷 배포를 추가로 요청했다. 기존 Vercel `robo-q3o3`와 Render `robo-capstone-api`를 사용한다. 새 과금 서비스·저장소 이전은 수행하지 않는다.

서버는 `python -m src.local.lab_meeting --from-env`로 계정을 준비한다. `CAPSTONE_LAB_ACCOUNTS_JSON`은 `cohort_id`와 13개의 `email`/`password_hash` 항목을 포함하는 서버 전용 설정이다. 비밀번호 원문은 받지 않고 Argon2id 해시만 받는다. `.work/lab-meeting/render-lab.env`는 Git에서 제외된 개인 설정 파일이다. Vercel·NEXT_PUBLIC 환경변수·클라이언트 코드에는 계정 해시를 넣지 않는다.

Render의 시작 명령과 환경은 `render.lab.yaml`을 기준으로 한다. 기존 12+1 초대 준비 명령을 함께 실행하지 않는다. 기존 데이터가 있는 다른 비교군에 계정을 덮어씌우지 않으며, 같은 랩미팅 DB가 유지되면 재실행해도 사용자가 변경한 비밀번호·선택·초안을 유지한다.

Vercel에는 기존 `FASTAPI_INTERNAL_URL`, `NEXT_PUBLIC_APP_PROFILE=local`, `NEXT_PUBLIC_CAPSTONE_DEMO=1`에 `NEXT_PUBLIC_LAB_MEETING=1`을 추가한다. 저장소의 추적된 `web/` 파일만 별도 경로에 내보내 배포하고 로컬 DB·계정 파일·캐시는 업로드하지 않는다.

무료 Render의 파일은 재배포·재시작·유휴 종료 때 사라질 수 있다. 서버 설정으로 13개의 초기 계정은 다시 준비되지만 **참가자가 저장한 선택·순위와 이후 변경한 비밀번호는 복원되지 않는다**. 랩미팅 중 사용과 장기 보관은 구분한다. 근거: [Render 무료 서비스 제한](https://render.com/docs/free).

서버 계정 해시 가져오기·기존 비밀번호/초안 보존·잘못된 계정 목록·평문 비밀번호 입력 차단·live 프로필 차단 등 관련 API 검사 15개가 통과했다. 원격 배포 완료와 원격 검증 결과는 완료 후 별도로 기록한다.
